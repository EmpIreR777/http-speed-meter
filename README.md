# http-speed-meter

Простой CLI-замерятель скорости интернета: принимает адрес тяжёлого ресурса
(большую картинку), последовательно делает 10 HTTP-запросов, дожидается каждого
ответа, считает среднее время запроса, объём скачанных данных и печатает
скорость в МБ/с и Мбит/с.

## Что делает программа

* принимает URL ресурса, который нужно скачивать;
* последовательно (не параллельно!) выполняет `N` запросов, по умолчанию `10`;
* полностью вычитывает тело каждого ответа, но не сохраняет его — считает только
  количество байт и затраченное время (`time.perf_counter()`);
* печатает таблицу по каждому запросу и суммарную статистику: среднее время,
  общий и средний объём, скорость в МБ/с и Мбит/с;
* возвращает осмысленный код завершения (см. «Коды возврата»), а при сбое печатает
  причину в `stderr`; умеет отдавать результат в JSON (`--json`).

Докстринги, комментарии и сообщения — на русском, точка входа вынесена
в отдельный модуль `main.py` (см. «Структура проекта»).

## Требования и установка

Нужны Python **3.14+** (проверено на 3.14.3) и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/EmpIreR777/http-speed-meter.git
cd http-speed-meter
uv sync   # создаст .venv на Python 3.14 и поставит зависимости из uv.lock
```

`uv sync` сам скачает нужную версию Python (если её нет) и поставит проект
в editable-режиме, так что отдельный `pip install` не нужен.

## Запуск

```bash
# замер по умолчанию: 10 последовательных запросов
uv run http-speed-meter https://upload.wikimedia.org/wikipedia/commons/f/ff/Pizigani_1367_Chart_10MB.jpg

# свои параметры: 5 запросов и таймаут 60 секунд на запрос
uv run http-speed-meter -n 5 -t 60 https://speed.cloudflare.com/__down?bytes=20000000

# машиночитаемый вывод
uv run http-speed-meter --json -n 3 https://proof.ovh.net/files/10Mb.dat
```

Эквивалент без консольной команды: `uv run python -m http_speed_meter <url>`.

## Опции командной строки

| Опция | Описание | По умолчанию |
| --- | --- | --- |
| `url` | обязательный позиционный аргумент: адрес тяжёлого ресурса | — |
| `-n`, `--requests N` | количество последовательных запросов | `10` |
| `-t`, `--timeout СЕК` | таймаут одного запроса | `30` |
| `--json` | вывести результат в JSON без промежуточных строк | выключено |
| `--version` | показать версию | — |

Полная справка: `uv run http-speed-meter --help`.

## Коды возврата

Коды не «0 — успех / 1 — ошибка», а осмысленные: по ним видно, что именно
сломалось, и в скриптах/CI можно реагировать на конкретную причину.

| Код | Константа | Когда возвращается |
| --- | --- | --- |
| `0` | `ExitCode.OK` | замер выполнен, отчёт напечатан |
| `1` | `ExitCode.FAILURE` | непредвиденная ошибка, не попавшая в таблицу ниже |
| `2` | `ExitCode.USAGE` | ошибка аргументов командной строки (этот же код отдаёт `argparse`) |
| `3` | `ExitCode.INVALID_URL` | адрес некорректен или протокол не поддерживается |
| `4` | `ExitCode.NETWORK` | сетевая ошибка: DNS, отказ в соединении, TLS |
| `5` | `ExitCode.TIMEOUT` | сервер не ответил за время `--timeout` |
| `6` | `ExitCode.HTTP_STATUS` | ответ пришёл с неуспешным статусом (не 2xx) |
| `130` | `ExitCode.INTERRUPTED` | прерывание по `Ctrl+C` (канонический `128 + SIGINT`) |

Проверить на практике: `uv run http-speed-meter not-a-url -n 1 ; echo $?` → `3`,
`... /files/missing.dat` → `6`, `-n 0` → `2`, рабочий адрес → `0`.

Ошибки живут в `errors.py`: `MeasurementError` (базовая), `InvalidURLError`,
`NetworkError`, `TimeoutMeasurementError`, `HTTPStatusMeasurementError`;
`exit_code_for(error)` сопоставляет исключение с кодом возврата.

## Как считаются метрики

* **Время запроса** — `time.perf_counter()` от начала запроса до последнего
  прочитанного байта тела ответа.
* **Объём данных** — сумма длин всех чанков тела ответа (`httpx` в режиме `stream`),
  без сохранения на диск.
* **Средняя скорость** — весь объём, делённый на всё время (устойчивее, чем среднее
  арифметическое скоростей отдельных запросов). Единицы десятичные:
  `1 МБ = 1 000 000 байт`, поэтому `Мбит/с = МБ/с × 8`.

## Структура проекта

```text
http-speed-meter/
├── pyproject.toml, uv.lock   # зависимости и их фиксация
├── Makefile                  # все команды проекта (make help)
├── .github/workflows/ci.yml  # ruff + mypy + pytest на каждый пуш
├── src/http_speed_meter/
│   ├── main.py               # ТОЧКА ВХОДА: main(), печать отчёта, коды возврата
│   ├── cli.py                # только argparse: build_parser()
│   ├── errors.py             # исключения замера, ExitCode и exit_code_for()
│   ├── models.py             # RequestMeasurement / SpeedReport и формулы
│   ├── measure.py            # сами запросы к адресу, серия замеров
│   ├── stats.py              # форматирование отчёта (таблица и JSON)
│   └── __main__.py           # запуск через python -m http_speed_meter
└── tests/
    ├── conftest.py           # локальный HTTP-сервер: ресурс, /slow и 404
    ├── test_measure.py       # замеры, агрегация и форматирование
    └── test_main.py          # сквозные проверки CLI и коды возврата
```

Разделение по файлам: интерфейс (`cli.py`), запуск (`main.py`), сеть (`measure.py`),
данные и формулы (`models.py`), ошибки и коды (`errors.py`), вывод (`stats.py`).
Точка входа одна — `main.main()`, её вызывают и команда `http-speed-meter`
(`[project.scripts]`), и `python -m http_speed_meter`. Тесты не ходят в интернет:
`conftest.py` поднимает локальный `http.server` с ресурсом на 64 КБ, `/slow` и 404.

## Разработка

Все команды собраны в `Makefile`: `make help` печатает список с описанием.

```bash
make sync          # .venv и зависимости (uv sync)
make run URL=https://proof.ovh.net/files/10Mb.dat REQUESTS=5
make format        # ruff format
make lint          # ruff check
make format-check  # проверка форматирования без правок
make typecheck     # mypy (strict)
make test          # pytest
make check         # format-check + lint + typecheck + test одной командой
make build         # собрать пакет в dist/
make clean         # удалить кэши, dist/ и .venv
```

Без `make` те же команды запускаются напрямую: `uv run ruff check .`,
`uv run mypy`, `uv run pytest` и так далее. Проект настроен на `ruff`
(E, W, F, I, N, UP, B, A, C4, SIM, RET, ARG, RUF) и `mypy --strict`.

## Ограничения

* Замер идёт по одному адресу: скорость ограничена не только каналом, но и сервером,
  CDN и кэшем провайдера — выбирайте большой файл.
* Запросы строго последовательные, «насыщающая» многопоточная нагрузка не создаётся
  (это требование задания). Ответ обязан быть 2xx, иначе код `6` или `3`.
